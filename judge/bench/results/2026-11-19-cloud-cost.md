# 클라우드 비용과 구독료 계산 (2026-11-19, #14)

지금 서비스는 학교 PC 한 대의 VM 3개(app·judge·llm)에서 돌아간다. 학교 PC는 서버비가 나오지 않으므로, 같은 서비스를 클라우드에 올렸을 때 한 달에 얼마가 드는지 계산했다. 그리고 그 비용을 구독료로 메우려면 유료 사용자가 몇 명 필요한지 계산했다.

측정값은 부하테스트 결과(`2026-11-18-load-test.md`)를 썼다. 실제로 클라우드에 올려 잰 값은 아니다.

## 1. 결과

동시 사용자 100명이 하루 24시간 쓰는 상황 기준이다. 서버는 모두 24시간 켜 두고, 한 달은 730시간으로 계산했다.

|---|---|---|

| 채점 | AWS `c7i.xlarge` × 2 | $294 |

### AI 방식별 월 비용

| AI 방식 | 구성 | AI 비용 | 전체 합계 |
|---|---|---|---|

- 자체 GPU 중에서는 RunPod A5000이 가장 싸다. AWS GPU는 같은 성능에 3~5배 비싸다.
- 외부 API는 쓴 만큼 낸다. 위 값은 100명이 24시간 내내 쓰는 경우라 실제로는 이보다 적다. GPU는 쓰지 않아도 같은 돈이 나간다.
- 외부 API에는 지금 쓰는 `gemma4:12b`가 없어 더 큰 모델(26b·31b)을 썼다. 답의 품질은 다시 확인해야 한다.

### 구독료와 유료 사용자 수

본전이 되는 유료 사용자 수다. 실제로 받는 돈은 구독료에서 부가세 10%와 결제 수수료 약 3%를 뺀 값으로 계산했다. 환율은 1달러 = 1,400원으로 가정했다.

| 구성 (월 비용) | 4,900원 | 9,900원 | 14,900원 |
|---|---|---|---|
| RunPod A5000 (약 144만 원) | 335명 | **166명** | 110명 |
| 외부 API 26b (약 134만 원) | 311명 | 154명 | 103명 |
| 외부 API 31b (약 190만 원) | 439명 | 218명 | 145명 |
| RunPod L40S (약 396만 원) | 917명 | 454명 | 302명 |
| AWS A10G (약 567만 원) | 1,314명 | 650명 | 432명 |
| AWS L40S (약 763만 원) | 1,767명 | 875명 | 581명 |

- 실제로 받는 돈은 4,900원이면 4,321원, 9,900원이면 8,730원, 14,900원이면 13,139원이다.
- 동시 100명이 24시간 유지되면 하루 이용자는 약 2,400명이다(1명이 하루 1시간 쓴다고 가정). 9,900원에 RunPod A5000이면 하루 이용자 중 약 7%가 유료여야 본전이다.
- 무료 사용자의 AI 사용(하루 20회 한도)도 위 비용에 이미 들어 있다. 모든 문제에서 AI를 쓴다고 계산했기 때문이다.

## 2. 계산 방법

### 가정

| 항목 | 값 | 근거 |
|---|---|---|
| 동시 사용자 | 100명 | 목표 |
| 문제 하나 푸는 시간 | 평균 10분 | 쉬움 5~10분, 보통 15~30분, 어려움 30분 이상보다 짧게 잡음. 짧을수록 요청이 많아 비용이 크게 나온다 |
| AI 사용 | 문제마다 1번 | 실제로는 누르지 않는 사람도 있으므로 넉넉하게 잡음 |
| 채점 요청 | 문제마다 예제 실행 3번 + 제출 2번 | 첫 제출이 오답이라 고쳐서 다시 내는 경우를 넣음 |
| 사용 시간 | 하루 24시간 | 코딩테스트 연습 서비스는 정해진 시험 시간이 없어 사용이 한때에 몰리지 않는다고 봄 |

이 가정으로 계산한 평소 요청 수는 다음과 같다.

- AI: 100명 ÷ 10분 = 분당 10건, 한 달 43.2만 건
- 채점: 100명 × 5건 ÷ 10분 = 분당 50건

### 서버 대수

| 항목 | 처리량 | 대수 | 바쁜 정도 |
|---|---|---|---|
| API·DB | 100명일 때 응답 중앙값 1ms 이하 (측정) | 1대 | 병목 아님. 로드밸런서도 필요 없음 |
| 채점 (4코어, 슬롯 4) | 1대 분당 100건 이상 (추정) | 2대 | 대당 약 25%. 1대로도 되지만 1대가 멈춰도 채점이 계속되도록 2대 |
| GPU A4000 | 분당 3.3건 (측정) | – | 비교 기준 |
| GPU A5000 | 분당 약 5.6건 (추정) | 3장 | 약 60% |
| GPU A10G | 분당 약 4.4건 (추정) | 4장 | 약 57% |
| GPU L40S | 분당 약 6.4건 (추정) | 3장 | 약 52% |

- 채점 서버는 1대당 슬롯 4개로 계산했다. 2대면 모두 8칸이다. 지금 운영은 슬롯 2이고, 4는 아직 적용하지 않았다(`2026-11-18-load-test.md` 2절).
- 채점 1대의 처리량은 부하테스트에서 잡았다. 슬롯 4에서 예제 실행 100건과 제출 100건이 1분 안에 몰렸는데, 90%가 45초 안에 끝났다.
- A4000이 아닌 GPU는 재지 않았다. 답을 만드는 속도가 GPU 메모리 속도에 거의 비례하므로, A4000(448GB/s) 측정값에 메모리 속도 비율을 곱했다(A5000 768, A10G 600, L40S 864GB/s).
- GPU는 바쁜 정도를 60% 안팎으로 잡았다. 요청이 잠깐 겹쳐도 줄이 길어지지 않게 하려는 여유다.
- L4(`g6.xlarge`, 시간당 $0.99)는 메모리 속도가 300GB/s로 A4000보다 느려 뺐다.

## 3. 사용이 몰릴 때

과제 마감처럼 사용이 한때에 몰리면 평소 구성으로는 부족하다. 부하테스트(100명이 1~3분 안에 모두 제출하고 AI를 요청)를 목표(채점 대기 90%가 5초 안, AI 대기 90%가 3분 안)에 맞추려면 다음만큼 필요하다.

| 항목 | 평소 | 몰릴 때 | 근거 |
|---|---|---|---|
| 채점 | 2대 | 8대 | 슬롯 4에서 4코어 1대가 CPU를 다 썼다. 1대에 12.5명이면 90%가 약 2초로 추정 |
| GPU (A5000) | 3장 | 4장 | AI 100건이 3분에 몰리면 분당 약 21건을 처리해야 함 |

- 몰릴 때 서버를 늘리는 데는 3~7분이 걸린다(서버 켜기, 이미지·모델 받기, 모델 올리기. 추정). 몰리는 것을 보고 늘리면 AI 대기 90%가 약 5~6분으로 목표를 넘는다. 마감 시각처럼 미리 아는 경우에는 그 전에 늘려 둔다.
- 쿠버네티스 HPA로 채점 서버 수를 자동으로 늘리고 줄일 수 있다. 늘린 동안의 추가 비용은 시간당 채점 6대 $1.21 + GPU 1장 $0.27이다.

## 4. 한계

- 클라우드에서 잰 값이 아니다. 학교 VM의 vCPU와 클라우드 vCPU는 성능이 다를 수 있다. 실제로 올리면 20~30% 여유를 두는 것이 안전하다.
- A4000이 아닌 GPU의 처리량은 메모리 속도로 추정했다. 1장을 1시간 빌려(약 $0.3~2.3) 같은 요청을 보내 보면 확인할 수 있다.
- 채점 서버를 2대로 늘리면 API의 `JudgeWorker.SLOTS`도 전체 칸 수(8)에 맞춰야 칸이 놀지 않는다.
- 디스크(EBS), 데이터 전송, DB 백업 비용은 넣지 않았다.
- RunPod을 쓰면 AWS와 다른 클라우드라 서버 사이 통신이 인터넷을 거친다. AI 대기 시간(분 단위)에 비하면 작다.
- 지금 코드는 API 서버 1대와 LLM 주소 1개를 전제로 한다. GPU를 늘려도 AI 대기열(`AiWorker`, API 메모리)이 새 GPU로 넘어가지 않는다. LLM 앞에 요청을 나눠 주는 서버를 두거나, 채점처럼 대기열을 DB로 옮겨야 한다.
- 가정(문제당 10분, 문제마다 AI 1번, 하루 1시간 사용)은 실제 사용 기록으로 확인하지 않았다. 사용자가 늘면 운영 DB의 제출 시각으로 다시 계산한다.
