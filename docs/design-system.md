# 디자인 시스템 — 여백 카드

Nov 8, 2026 · @찬우

화면의 색·모양을 정한 기준이다. 팀이 시안 여러 개를 비교해 **여백 카드**로 정했다(2026-11-08, 재환·정민·찬우).
값은 `web/src/index.css`에 있고, 이 문서는 왜 그 값인지와 어떻게 쓰는지를 적는다.

## 1. 방향

회색 바탕 위에 선·그림자 없는 흰 카드를 놓고, 여백과 글자 크기로 위계를 만든다. 포인트 색 인디고는 주 버튼·링크·선택된 것에만 쓴다.

정한 이유는 학습자가 화면을 쓰는 방식이다.

- **틀려도 덜 부담스럽게.** 학습자는 '틀렸습니다'를 맞았을 때보다 자주 본다. 판정을 화면 전체 색면으로 채우지 않고 카드 위 색 글자 + 아이콘으로 조용하게 보여 준다.
- **오래 봐도 피곤하지 않게.** 풀이 화면에는 30분~1시간씩 머문다. 선과 그림자를 줄여 지문과 코드에 눈이 가게 한다.
- **진행이 보이게.** 맞힌 수·연속 학습 같은 숫자를 크게 보여 장식 없이도 성취감을 준다.

## 2. 적용 단계

화면 전체가 바뀌는 일이라 세 단계로 나눠 PR을 따로 올린다. 모든 단계에서 동작·문구·API는 바꾸지 않는다.

| 단계 | 이슈 | 바꾸는 곳 |
| --- | --- | --- |
| 1. 색 토큰 | #208 | `web/src/index.css`의 색 값 |
| 2. 공용 컴포넌트 | #211 | `web/src/components/ui/` (버튼·입력칸·표·탭·메뉴·대화상자)와 둥글기 |
| 3. 화면별 정리 | #212 | `web/src/features/` (카드·판정 표시·제목 크기) |

## 3. 색

포인트 색 `#586FC4` 하나에서 밝은 쪽·어두운 쪽 단계를 나눴다. 회색도 같은 색상(인디고 쪽 푸른 기)으로 맞췄다.
shadcn 변수 이름은 그대로 두고 값만 바꿨다. 그래서 `bg-primary` `text-muted-foreground` 같은 기존 클래스가 그대로 새 색을 쓴다.

### 기본 변수

| 변수 | 쓰임 | 밝은 모드 | 다크 모드 |
| --- | --- | --- | --- |
| `--background` | 페이지 바탕 | `#F2F4FB` | `#0C0E13` |
| `--card` `--popover` | 카드·메뉴 면 | `#FFFFFF` | `#1C1E23` |
| `--foreground` | 본문 글자 | `#1C1E23` | `#F2F4FB` |
| `--muted` `--secondary` | 옅은 면, 보조 버튼 | `#E5E8EE` | `#282A30` |
| `--muted-foreground` | 보조 글자 | `#505258` | `#B2B4BA` |
| `--primary` | 주 버튼 채움 (글자로 쓰지 않음) | `#586FC4` | `#586FC4` |
| `--primary-foreground` | 주 버튼 글자 | `#FFFFFF` | `#FFFFFF` |
| `--primary-text` | 링크·강조 글자 | `#354589` | `#91A3DA` |
| `--primary-hover` | 주 버튼 올림 면 | `#465AA9` | `#465AA9` |
| `--accent` | 선택·올림 면 | 인디고 10% | 인디고 16% |
| `--accent-foreground` | 그 위 글자 | `#354589` | `#91A3DA` |
| `--border` | 선 | `#D2D4DA` | `#3B3D42` |
| `--input` | 입력칸 테두리 | `#6A6C71` | `#6A6C71` |
| `--ring` | 포커스 링 | `#586FC4` | `#7086D0` |

- 주 버튼은 다크 모드에서도 같은 인디고에 흰 글자다. 밝은 인디고에 어두운 글자로 바꾸면 모드마다 버튼 인상이 달라진다.
- **`--primary`는 채움 전용이다.** 그대로 글자로 쓰면 밝은 모드 바탕 위 4.26:1, 다크 모드 카드 위 3.56:1이라 링크가 읽기 어렵다. 링크·강조 글자는 `text-primary-text`를 쓴다.
- 주 버튼 올림은 면을 옅게(`bg-primary/80`) 하지 않고 한 단계 진한 `bg-primary-hover`로 바꾼다. 흰 글자를 올린 채 옅게 하면 3.2:1로 떨어진다.
- `--input`은 `--border`보다 진하다. 입력칸은 경계가 보여야 쓸 수 있는 부품이라 3:1이 필요하고, 선(`--border`)은 장식이라 그 기준이 없다.

### 판정 색

판정은 네 묶음만 쓴다. 다른 곳에 초록·빨강·노랑을 쓰지 않는다.

| 묶음 | 판정 | 변수 |
| --- | --- | --- |
| 위험 | 틀렸습니다, 출력 형식, 런타임 에러, 컴파일 에러 | `destructive` |
| 성공 | 맞았습니다!! | `success` |
| 경고 | 시간·메모리·출력 초과 | `warning` |
| 정보 | 채점 중, 안내 | `info` |

채점 불가는 판정 색 없이 `muted`를 쓴다(서버 문제이지 학습자의 잘못이 아니다).

묶음마다 네 가지 변수가 있다.

| 접미사 | 쓰임 | 예 |
| --- | --- | --- |
| (없음) | 채움 면 | `bg-success` |
| `-foreground` | 채움 면 위 글자 | `text-success-foreground` |
| `-soft` | 옅은 면 (12%, 다크 16%) | `bg-success-soft` |
| `-text` | 카드나 옅은 면 위 글자 | `text-success-text` |

**글자에는 `-text`를 쓴다.** 채움 색을 글자색으로 쓰면 밝은 모드의 경고(노랑)는 흰 카드 위에서 1.88:1, 정보(청록)는 3.35:1이라 읽기 어렵다.

## 4. 대비

글자 4.5:1, 입력칸 테두리·포커스 링 3:1(WCAG 2.1 AA)을 기준으로 계산했다. 반투명 면은 카드 위에 겹친 색으로 계산했다.

| 링크 글자 / 바탕 | 8.08 | 7.77 |
| 링크 글자 / 카드 | 8.88 | 6.71 |

- 밝은 모드 입력칸 테두리는 처음에 한 단계 옅은 `#8D8F95`였는데, 회색 바탕 위에서 2.94:1이라 `#6A6C71`로 올렸다.
- 처음 표는 버튼 채움만 계산해, 같은 색을 글자로 쓰는 조합(링크, 위험 버튼 글자)과 올림·비활성 상태를 놓쳤다(#213 리뷰). 색을 바꿀 때는 **그 변수를 쓰는 클래스를 모두 찾아** 글자인지 면인지, 어떤 면 위에 놓이는지까지 계산한다.
- 비활성 탭은 `text-foreground/60`(밝은 모드 4.11:1) 대신 `text-muted-foreground`를 쓴다.

## 5. 모양

### 공용 컴포넌트 (2단계, #211)

`web/src/components/ui/`의 부품에 반영했다. 부품을 쓰는 화면은 따로 고치지 않아도 이 모양이 된다.

| 대상 | 값 |
| --- | --- |
| 둥글기 | `--radius: 0.75rem`. 버튼 `rounded-lg` 12px, 메뉴 `rounded-xl` 약 17px, 대화상자·카드 `rounded-2xl` 약 22px. 입력칸은 둥글기 없는 밑줄형(`rounded-none`) |
| 버튼 높이 | 기본 40px(`h-10`), `lg` 48px, `sm` 32px, `xs` 28px. 아이콘 버튼도 같은 단계 |
| 버튼 글자 | 14px · 600 |
| 중요한 버튼 | `size="lg"`는 화면에서 가장 중요한 버튼에만 쓴다 (로그인·가입 제출, 문제 풀이 제출) |
| 보조 버튼 | `outline`: 흰 면 + 얇은 선. 회색 바탕 위에 바로 놓이는 곳이 많아서다. 다크 모드는 면과 바탕이 거의 같아 선을 `--input`(3.2:1 이상)으로 둔다. 회색 면 `secondary`는 흰 카드 위에서 쓴다 |
| 입력칸 | 밑줄 2px(`--input`, 3:1), 바탕 없음. 포커스하면 밑줄이 4px로 두꺼워지고 포인트 색이 된다. 회색→포인트 색 변화는 명도 차가 1.1:1뿐이라, 포커스는 새로 칠해지는 2px 띠(바탕·카드와 3:1 이상)로 알린다. 오류면 밑줄과 포커스 띠 모두 위험색 |
| 표 | 줄 사이 선 없음, 올리면 옅은 면. 머리줄은 바탕 없이 12px 보조 글자, 칸 위아래 12px. 로딩 자리표시자(`ListSkeleton`)도 같은 모양으로 선 없음 |
| 탭 | 기본이 밑줄(`line`). 선택된 탭은 진한 글자색 2px 밑줄, 나머지는 보조 글자 |
| 메뉴·대화상자 | 밝은 모드는 선 없이 `shadow-float`. 다크 모드는 그림자가 잘 안 보여 얇은 선(`ring-border`)을 함께 둔다 |

- 밑줄 탭은 탭 목록의 위아래 여백(3px)을 없앴다. 탭과 탭 목록에 둘 다 `min-h-11`(터치 44px)을 걸면 여백만큼 넘쳐 세로 스크롤이 생겼다.

### 화면별 정리 (3단계, #212에서 할 것)

- 카드: 선·그림자 없음. 회색 바탕과 흰 카드(`bg-card rounded-2xl`)의 색 차이로 나눈다
- 판정·풀이 상태: 색 면 배지 대신 `-text` 글자 + 아이콘
- 제목: 화면 제목은 크고 굵게, 리포트·마이페이지 숫자도 크게
- 흰 카드가 생긴 곳의 보조 버튼은 `outline`에서 회색 면 `secondary`로 바꾼다
- 관리자 화면의 직접 만든 선택 상자(`select`)·여러 줄 입력칸(`textarea`)은 아직 테두리 상자다. `Input`과 같은 밑줄형(`rounded-none`, 밑줄 2px, 포커스 4px)으로 맞춘다. 둥근 상자로 맞추지 않는다
- 문제 목록 필터의 `size="lg"` 보조 버튼은 중요한 버튼이 아니라 기본 크기로 바꾼다
