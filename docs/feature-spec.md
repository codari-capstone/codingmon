# 프론트엔드 기능명세서 — AI 기반 코딩테스트 학습 플랫폼

Oct 3, 2026 · @찬우

## 개요

학습자와 관리자가 화면에서 쓰는 기능을 화면별로 정리했다. 기준은 졸업작품 계획서(2026.09.28)이며, 채점 비교·프롬프트·추천 계산 같은 서버 내부 처리는 화면에 보이는 부분만 적었다.

- **ID 규칙**: 화면 약어-번호. COM 공통, LIST 문제 목록, SOLVE 문제 풀이, RES 제출 결과, AI 분석·힌트·리뷰, HIST 제출 기록, REP 학습 리포트, ADM 관리자, UX 공통 처리, MY 마이페이지, STREAK 연속 학습, BADGE 배지
- **우선순위**: 필수 = 7주차 MVP에 포함, 선택 = 일정이 남으면 구현

### 기능 맵

학습자 화면에 기능 51개, 관리자 화면에 16개, 모든 화면 공통으로 14개가 있다. 각 기능의 설명은 아래 화면별 표에 있다.

## 1. 공통

| ID     | 기능            | 설명                                                                             | 우선순위 |
| ------ | --------------- | -------------------------------------------------------------------------------- | -------- |
| COM-01 | 상단 내비게이션 | 로고, 문제·제출 기록·내 학습 메뉴, 로그인 상태가 보이는 사용자 메뉴(닉네임을 누르면 마이페이지·내 학습·로그아웃) | 필수     |
| COM-02 | GitHub 로그인   | 부가 가입·로그인 수단. GitHub OAuth로 로그인하고, 성공하면 원래 보던 페이지로 돌아감. 처음이면 닉네임 입력(빈칸에서 시작, 중복 확인) 후 가입 완료(그 사이 닉네임이 선점되면 다시 입력). 비밀번호는 만들지 않음. GitHub 계정 하나에 계정 하나(GitHub 고유 ID로 구분해 사용자명이 바뀌어도 같은 계정). GitHub 이메일은 받지도 저장하지도 않음(이메일 권한 요청 없음). 그래서 같은 사람이 이메일 가입 계정과 GitHub 계정을 따로 가질 수 있음. 이미 가입한 GitHub 계정(고유 ID 일치)이면 바로 로그인 | 필수     |
| COM-03 | 로그아웃        | 사용자 메뉴에서 로그아웃하면 문제 목록으로 이동                                  | 필수     |
| COM-04 | 로그인 유지     | 토큰이 만료되면 자동으로 갱신하고, 실패하면 로그인 화면으로 보냄                 | 필수     |
| COM-05 | 권한별 접근     | 비로그인은 문제 목록만 보고, 문제를 열면 로그인 화면으로 보냄. 문제 풀이·제출·AI·리포트·마이페이지·배지는 로그인 필요, 관리자 메뉴는 ADMIN만 표시 | 필수     |
| COM-06 | 이메일 회원가입 | 기본 가입 수단. 한 화면에서 이메일 인증번호 확인, 닉네임 \[중복 확인\], 비밀번호·비밀번호 확인을 마쳐야 \[가입 완료\] 활성화(인증하거나 확인한 값을 바꾸면 다시 확인). 인증 후 30분이 지나면 이메일을 다시 인증. 가입 완료 시점에 닉네임이 선점됐으면 다시 입력. 인증번호·닉네임·비밀번호 규칙은 아래 '계정 규칙'. 가입을 마치면 로그인 화면으로 보내고 '가입이 완료됐어요. 로그인해 주세요'를 띄움(가입만으로는 로그인되지 않음). 로그인이 필요한 화면에서 넘어왔으면 로그인 뒤 그 화면으로 감. 닉네임·비밀번호 규칙을 어겨 실패하면 그 값만 고쳐 다시 제출(이메일 인증은 유지) | 필수     |
| COM-07 | 이메일 로그인   | 이메일·비밀번호로 로그인하고, 성공하면 원래 보던 페이지로 돌아감. 실패하면 이유와 관계없이 같은 문구('이메일 또는 비밀번호가 맞지 않아요. GitHub로 가입했다면 GitHub 로그인을 이용해 주세요'). 같은 이메일로 5회 연속 실패하면 5분 동안 로그인 제한. 제한 중에는 '로그인 시도가 너무 많아요. 5분 후 다시 시도해 주세요'. 가입되지 않은 이메일도 같은 기준으로 제한. 재설정(COM-08)으로 비밀번호를 바꾸면 이 제한이 풀림 | 필수     |
| COM-08 | 비밀번호 재설정 | 로그인 화면의 \[비밀번호 찾기\]에서 이메일 → 인증번호 확인 → 새 비밀번호·확인 입력. 인증 후 10분 안에 새 비밀번호를 제출해야 하고, 지나면 '인증 시간이 지났어요. 인증번호를 다시 받아 주세요'. 재설정하면 모든 기기에서 로그아웃(발급된 로그인 유지 토큰 폐기). 인증번호는 일반 가입 계정에만 보냄(그 밖의 이메일은 아래 '가입 여부 안내'). 재설정을 마치면 로그인 화면으로 보내고 '비밀번호를 바꿨어요. 새 비밀번호로 로그인해 주세요'를 띄움 — 이 안내에 '모든 기기에서 로그아웃됐다'는 적지 않음(바로 다시 로그인하므로 할 일이 달라지지 않고, 다른 기기는 토큰 갱신이 실패해 로그인 화면으로 가며 드러남). 재설정하면 그 이메일에 걸린 로그인 제한(COM-07)도 풀려 새 비밀번호로 바로 로그인할 수 있음. 새 비밀번호가 현재 비밀번호와 같으면 '지금 쓰는 비밀번호와 같아요. 다른 비밀번호를 입력해 주세요'(해킹이 의심돼 재설정해도 비밀번호를 아는 사람이 다시 로그인할 수 있으므로). 비밀번호 규칙을 어기거나 현재 비밀번호와 같아 실패하면 비밀번호만 고쳐 다시 제출 | 필수     |

### 계정 규칙

- **인증번호** (COM-06·08): 6자리, 5분 만료, 5회 틀리면 무효('입력 횟수를 초과했어요. 인증번호를 다시 받아 주세요'). 다시 보내면 이전 번호는 무효.
- **발송 제한** (COM-06·08): 이메일마다 1분 간격·하루 5회, 같은 IP에서 하루 20회. 가입과 재설정은 따로 센다.
- **가입 여부 안내** (COM-06·08): \[인증번호 받기\]에서 아래 경우에는 인증번호를 보내지 않고 화면에 알린다. 이 조회는 IP 기준(하루 20회)에만 세고, 이메일 기준(1분 간격·하루 5회)은 인증번호를 실제로 보낼 때만 센다.
  - 회원가입에서 이미 가입된 이메일: '이미 가입된 이메일이에요' + \[로그인하러 가기\](로그인 화면으로 이동)
  - 재설정에서 가입되지 않은 이메일: '가입되지 않은 이메일이에요. 이메일을 정확히 입력해 주세요'
  - 발송 제한에 걸리면: '요청이 너무 많아요. 잠시 후 다시 시도해 주세요'
- **닉네임** (COM-02·06): 2\~16자, 한글·영문·숫자만. 대소문자 구분 없이 중복 확인('Alice'와 'alice'는 같은 닉네임).
- **비밀번호** (COM-06·08): 10\~20자, 영문 대문자·소문자·숫자·특수문자 각 1개 이상. 로그인(COM-07)에서는 이 규칙을 검사하지 않는다.
- **이메일 형식** (COM-06·08): 인증번호 발송·확인에서 형식을 검사하고, 형식이 아니면 '이메일 형식이 올바르지 않아요'. 화면이 보내기 전에 미리 검사할 때도 같은 문구를 쓴다 — 같은 조건에 두 문장이 있으면 어디서 걸렸는지에 따라 사용자가 다른 말을 듣는다.
  - 로그인(COM-07)에서는 **검사하지 않는다.** 실패 이유를 가르지 않기로 했으므로(위 COM-07) 형식 오류도 같은 문구여야 한다. 로그인 화면이 보내기 전에 하는 검사는 **가입이 받아 주는 주소를 모두 통과시켜야 한다** — 그보다 엄격하면 그 주소로 가입한 사람이 자기 주소를 넣을 수 없고, 단일 문구 때문에 이유도 알 수 없다.

- **난이도별 맞힌 수**: 공개 중인 버전의 난이도로 센다. 공개가 내려간 문제도 세고, 마지막으로 공개됐던 버전의 난이도를 따른다. 제출 기록(HIST-01)은 마지막 제출 버전을 보여 주므로 관리자가 난이도를 바꾼 문제는 서로 다를 수 있다.
- **잔디에 세는 제출**: 사용자 제출이면 판정과 관계없이 센다(틀림, 채점 중, 채점 불가 포함). 예제 실행과 관리자의 정답 코드 검증은 세지 않는다. 결과가 아니라 공부한 날을 보여 주기 때문이다.
- **날짜**: 한국 시각 자정으로 날을 나눈다. AI 한도는 UTC 기준이지만 잔디는 날짜 칸이 그대로 보이므로 실제로 푼 날과 맞춘다.
- **범위**: 오늘을 포함한 최근 365일이다. 총 활동일도 이 안에서만 센다.

## 11. 연속 학습

매일 조금씩 이어서 풀도록 며칠째 이어서 공부했는지 보여 준다.

| ID        | 기능            | 설명 | 우선순위 |
| --------- | --------------- | ---- | -------- |

| STREAK-02 | 연속 학습 칩    | 상단 바에 연속 일수를 보여 줌 | 필수     |

연속 학습의 기준은 다음과 같다. 무엇을 세는지와 하루를 나누는 시각은 MY-05 잔디와 같다. 다만 잔디처럼 최근 365일만 보지 않고 기간 제한 없이 센다.

- **세는 제출**: 사용자 제출이 하루에 한 번이라도 있으면 그날이 이어진다. 판정과 관계없이 센다(틀림, 채점 중, 채점 불가 포함). 예제 실행과 관리자의 정답 코드 검증은 세지 않는다. 결과가 아니라 공부한 날을 세기 때문이다.
- **날짜**: 한국 시각 자정으로 날을 나눈다.
- **오늘 아직 안 했을 때**: 어제까지 이어졌으면 그 일수를 그대로 보여 준다. 예: 월·화·수에 제출했으면 목요일에 제출하기 전에는 3일째, 제출하면 4일째다. 목요일을 건너뛰면 금요일에 0일째다.
- **이번 주 달력**: 한국 시각 월요일~일요일로 고정한다. 월요일 0시에 새 주로 넘어가 칸이 모두 비지만, 연속 일수는 주가 바뀌어도 이어진다.
- **비로그인**: 카드와 칩을 0일째·빈 달력으로 보여 준다.

| 11   | `INTERMEDIATE`  | 중급자       | 쉬움 20개, 보통 절반(10개 이상), 어려움 4분의 1(2개 이상) 맞히기. 공개 중인 문제 기준 |
| 12   | `MASTER`        | 마스터       | 공개 중인 문제 모두 맞히기 |

배지의 기준은 다음과 같다.

- **세는 제출**: 연속 배지를 뺀 배지는 사용자 제출이 판정을 받은 것만 센다. 예제 실행, 관리자의 정답 코드 검증, 채점 불가는 세지 않는다.
- **맞힘·틀림**: 문제를 처음 맞힐 때까지의 제출만 본다. 맞힌 뒤 다시 틀리거나 다시 맞혀도 바뀌지 않는다. 컴파일 에러도 틀림으로 센다.
- **연속 일수**: STREAK-01과 같다. 판정과 관계없이 제출한 날을 세므로 틀린 제출로도 연속 배지를 받는다. 일수가 한 번이라도 3·7·14에 닿으면 준다.
- **보통 이상**: 보통과 어려움이다.
- **힌트 없이**: 맞힐 때까지 힌트를 한 단계도 열지 않았어야 한다. 힌트는 틀린 뒤에 열 수 있어 처음 맞힌 제출 전에 한 번 이상 틀렸어야 한다.
- **다시 도전·끈기**: 그 문제를 처음 맞힐 때까지 틀린 횟수로 본다. 다시 도전은 1번 이상, 끈기는 5번 이상이다. 날짜는 보지 않는다.
- **난이도**: 공개 중인 버전의 난이도를 따른다. 공개가 내려간 문제는 마지막으로 공개됐던 버전을 따른다(MY-05와 같음).
- **맞힌 수**: 보통은 MY-05처럼 공개가 내려간 문제도 센다. 중급자와 마스터는 공개 중인 문제만 센다. 그래서 마이페이지의 맞힌 수와 다를 수 있다.
- **중급자의 비율**: 공개 중인 문제 수에 곱하고 올림한다. 예: 보통이 25개면 절반은 13개이고, 10개보다 많으니 13개를 맞혀야 한다.
- **주는 시점**: 제출의 채점이 끝날 때 확인한다. 한 제출로 여러 배지를 받을 수 있다.
- **유지**: 받은 배지는 조건이 깨져도 남는다. 예: 연속이 끊기거나 새 문제가 올라와도 마스터가 남는다.
- **이전 기록**: 배지 기능 전에 맞힌 문제도 맞힌 수에는 들어간다. 그래서 보통·중급자·마스터는 다음에 문제를 처음 맞힐 때 받을 수 있다. 나머지는 기능이 생긴 뒤의 제출부터 본다. 연속 일수는 연속 학습 기능이 생긴 뒤부터 센다.
