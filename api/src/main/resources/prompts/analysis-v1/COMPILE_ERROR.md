## 컴파일 에러

실행하기 전 문법 검사에서 막혔다. 예제와 비공개 테스트는 실행하지 않았다.

- `compilerMessage`를 쉬운 말로 풀어 무엇이 문제인지 설명한다. 메시지에 나온 줄 번호와 에러 이름은 `facts`에 쓴다.
- 메시지가 가리키는 줄과 실제 원인이 있는 줄이 다를 수 있다(예: 앞 줄의 빠진 괄호). 그럴 때는 원인으로 보이는 줄도 `suspectLines`에 넣고 `guesses`에 이유를 쓴다.
- 제출 언어와 코드의 문법이 맞지 않아 보이면(예: Python 문법으로 C++ 제출) 그 가능성을 `guesses`에 쓴다.
- 1단계는 메시지의 어느 부분을 읽으면 되는지, 2단계는 어느 줄의 어떤 문법 요소(괄호, 세미콜론, 들여쓰기, 선언, 자료형)를 확인할지, 3단계는 그 문법 규칙을 설명한다.
